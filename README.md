# 国际义诊候选分配

本项目把候选事件整理为一套**可解释的分配流程**领域约定，供业务、运营和研发在同一套术语下讨论。资料只包含领域模型与内存参考实现，不包含真实个人信息、生产连接或外部账号。

## 设计原则

- **自动排序只产生建议**：筛查结果、适应证、紧急程度、地区公平目标、名额技能、行程窗口、语言支持、知情授权、后续照护承诺共同参与排序，但输出只是 `CANDIDATE_RANKED` 建议；占有与归属必须由协调员动作触发。
- **先过硬门限，再看加权分**：门限不满足时排名再高也不可建议，签证、随访、语言、窗口等问题在排序阶段即暴露，而不是留到最后；每条建议都带逐因素解释。
- **一切状态变化都是事件**：筛查更正、航班变化都以新事件表达，日志追加式存储并带哈希链，可校验、可截断复算。
- **自动与人工分离**：例外必须由独立复核人（非申请人、非接诊链成员）批准并记录影响，凭批准才能绕过门限建立归属。

## 目录

- `src/domain.py`：事件类型、字段校验、时间戳规范与哈希链。
- `src/ranking.py`：纯函数排序内核——门限 + 加权因子，输出可解释建议。
- `src/service.py`：分配服务——占有/到期/递补、并发确认、例外复核、披露、重算边界、重启恢复与审计复算。
- `src/medical_mission_allocation.py`：历史入口，保持 `validate_event` 等旧 API 兼容。
- `data/sample.json`：用于核对资料格式的虚构事件。
- `tests/`：覆盖以下每条规则的契约测试。

## 规则与事件映射

| 业务要求 | 实现方式 |
| --- | --- |
| 可解释排序 | 七项门限（筛查/适应证/窗口/语言/授权/随访/材料）+ 三项加权因子（紧急程度 0.5、地区公平 0.35、窗口余量 0.15），建议含门限明细、因子贡献与公平缺口标记 |
| 自动结果仅为建议 | `CANDIDATE_RANKED` 不改变任何占有/归属；协调员另行 `place_hold` / `confirm` |
| 名额暂占有期限 | `SLOT_HELD` 带 `expires_at`，`sweep_expired()` 到期释放；逾期者回候补池，不自动立即拿回 |
| 退出/材料过期后递补 | `CANDIDATE_WITHDRAWN` / `MATERIAL_EXPIRED` → `HOLD_RELEASED`（未出发已确认则 `ALLOCATION_REVOKED`）→ 按原排序 `WAITLIST_PROMOTED` |
| 跨合作方不重复占位 | 同一患者有效占有或归属唯一；冲突记 `HELD_BY_OTHER_PARTNER`，另有合作方本地别名映射防同人多号 |
| 并发确认单归属 | 服务内加锁 + 归属表唯一约束；`request_key` 幂等，重试不产生第二条归属 |
| 独立例外复核 | `EXCEPTION_REQUESTED` → 复核人非申请人且非接诊链成员、必须填写影响 → `EXCEPTION_APPROVED` / `EXCEPTION_REJECTED` |
| 身份最小披露 | `disclose_identity` 只对名额实际接诊链放行，每次 `DISCLOSURE_MADE` 留痕 |
| 重算边界 | 筛查更正/航班变化只重算未出发安排；`PATIENT_DEPARTED`、`CARE_COMPLETED` 为锁定事实，不可变 |
| 重启不重复 | 派生事件（释放/升级/通知）使用确定性事件 ID；恢复时校验哈希链并重放投影，到期释放、候补升级、交接通知恰好一次 |
| 审计复算 | 归属事件固定 `data_version`（日志头哈希）、权重与公平目标快照；`audit_allocation` 截断重放，复出门限结果与分数，任何篡改被哈希链检出 |
